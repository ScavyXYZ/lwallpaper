### A lightweight Windows live wallpaper manager written in C++

Turn your favorite videos into beautiful animated desktop wallpapers.

## ✨ Features

- 🎬 **Video wallpapers** — use your own videos as animated wallpapers
- 🖥️ **Automatic screen adaptation** — videos are transcoded to the current screen resolution
- ⚡ **Hardware decoding** — uses D3D11VA when supported by the video codec/GPU
- 🔄 **Seamless looping** — wallpapers automatically restart when the video reaches the end
- 🗂️ **Wallpaper library** — keep multiple wallpapers and switch between them
- ➕ **Easy importing** — add videos directly from the GUI
- ❌ **Wallpaper management** — remove wallpapers you no longer need
- 🖱️ **System tray support** — close the window without actually stopping the application
- 🚀 **Autostart support** — restore the last selected wallpaper on application startup
- 🔒 **Single-instance protection** — launching the application twice brings the existing instance to the foreground
- 🧵 **Multithreaded playback** — video decoding and wallpaper playback run independently from the UI
- 🎯 **Frame timing** — frames are rendered according to their presentation timestamps for smoother playback
- ⚙️ **Efficient importing** — compatible H.264 videos are copied directly; other videos are converted without upscaling, with hardware encoding when available

## 🛠️ Tech Stack

LWallpaper combines several technologies to provide smooth video playback directly on the Windows desktop.

| Technology | Purpose |
|---|---|
| **C++** | Core application logic |
| **Qt Widgets** | Graphical user interface |
| **SDL3** | Rendering video frames |
| **FFmpeg** | Video decoding and transcoding |
| **Win32 API** | Windows desktop integration |
| **D3D11VA** | Optional hardware-accelerated video decoding |

The application uses FFmpeg's format, codec and scaling APIs for decoding and pixel-format conversion.

SDL3 is used to create the rendering window and display YUV video frames.

## Building on Windows

Requires CMake 3.21+, Visual Studio with Desktop development with C++, a Windows
SDK, and Qt Widgets for MSVC x64. Tested with Visual Studio 2026 and Qt 6.11.1.
See [third_party/README.md](third_party/README.md) for native dependencies.

```powershell
git lfs install
git lfs pull
./scripts/build.ps1 -QtRoot C:/Qt/6.11.1/msvc2022_64
```

The script builds Release x64 and copies Qt plugins and runtime DLLs next to:

```text
build/bin/Release/lwallpaper.exe
```

`-QtRoot` defaults to the `QTDIR` environment variable. Use `-Configuration Debug`
for a debug build. For Visual Studio 2022, use a separate build directory:

```powershell
./scripts/build.ps1 -QtRoot C:/Qt/6.11.1/msvc2022_64 `
    -Generator "Visual Studio 17 2022" -BuildDirectory build/vs2022
```

Or configure CMake directly:

```powershell
cmake -S . -B build -G "Visual Studio 18 2026" -A x64 `
    -DQt6_ROOT=C:/Qt/6.11.1/msvc2022_64
cmake --build build --config Release --parallel
```

CMake is the only build definition. In Visual Studio, use **Open Folder** on the
repository root and configure `Qt6_ROOT` to point to your Qt MSVC installation.
Alternatively, open the solution generated by CMake inside `build/`. Qt VS
Tools and handwritten `.vcxproj` files are not required.

The Microsoft Visual C++ x64 runtime must be installed on the destination PC.
Copy the **whole output directory**, not just the executable.

## Tests

```powershell
ctest --test-dir build -C Release --output-on-failure
```

Tests are built by default (`-DBUILD_TESTING=OFF` disables them). Media tests
require a separate `ffmpeg` CLI on `PATH` and PowerShell; without these tools
only the unit test is registered. The D3D11 integration test uses a private
hidden window, never the desktop wallpaper, and is skipped if the required
GPU/driver support is unavailable. See [docs/performance.md](docs/performance.md).

## Installer

After a Release build, open `packaging/lwall.iss` in Inno Setup. Place Microsoft's
`VC_redist.x64.exe` in `packaging/redist/` first. The installer reads the CMake
Release output by default; override the `BuildDir` preprocessor variable to
package another output directory. Installer output goes to `build/installer/`.

## 🎥 Supported Video Formats

The GUI currently allows importing:

- `.mp4`
- `.mkv`
- `.webm`
- `.avi`

Compatible 8-bit H.264 videos that fit the screen are copied without re-encoding.
Other inputs are encoded to H.264, preserving aspect ratio and never enlarging
the source resolution. Import tries NVENC, QSV and AMF, then falls back to
software libx264 when those encoders cannot be initialized. Hardware encoding
uses a resolution/FPS-adjusted bitrate; software encoding uses CRF 23.
Imports are published only after completion, so cancellation does not leave a
half-written library entry.
